#ttl #пакет
**TTL в ping** (Time To Live) **обозначает «Время жизни пакета»**
Это значение определяет, сколько раз пакет может быть переслан от одного устройства к другому (такие пересылки называются «хопами»). Каждый раз, когда пакет пересылается, значение TTL уменьшается на 1. Как только этот параметр у пакета становится равен нулю, маршрутизатор удаляет пакет.

Значение TTL зависит от версии операционной системы и устройства. По умолчанию начальное значение TTL для Linux/Unix — 64, а для Windows — 128

## **Утилита `netstat`**
`netstat` (network statistics) — это утилита для отображения сетевых соединений, таблиц маршрутизации, статистики интерфейсов и многого другого.
### Основные флаги `netstat`:

- **`-a` (all)**:
    
    - Показывает все активные соединения и ожидающие (listening) порты.
        
    - Пример:
        
        bash
        
        Copy
        
        netstat -a
        
- **`-t` (TCP)**:
    
    - Показывает только TCP-соединения.
        
    - Пример:
        
        bash
        
        Copy
        
        netstat -at
        
- **`-u` (UDP)**:
    
    - Показывает только UDP-соединения.
        
    - Пример:
        
        bash
        
        Copy
        
        netstat -au
        
- **`-n` (numeric)**:
    
    - Отображает IP-адреса и порты в числовом формате (без разрешения имён).
        
    - Пример:
        
        bash
        
        Copy
        
        netstat -an
        
- **`-l` (listening)**:
    
    - Показывает только порты, находящиеся в состоянии ожидания (listening).
        
    - Пример:
        
        bash
        
        Copy
        
        netstat -l
        
- **`-p` (program)**:
    
    - Показывает PID и имя процесса, использующего соединение.
        
    - Пример:
        
        bash
        
        Copy
        
        netstat -ap
        
- **`-r` (route)**:
    
    - Показывает таблицу маршрутизации.
        
    - Пример:
        
        bash
        
        Copy
        
        netstat -r
        
- **`-s` (statistics)**:
    
    - Показывает статистику по протоколам (TCP, UDP, ICMP и т.д.).
        
    - Пример:
        
        
        netstat -s
        
- **`-c` (continuous)**:
    
    - Обновляет вывод каждую секунду (режим реального времени).
        
    - Пример:
        netstat -c
## **Утилита `lsof`**
`lsof` (list open files) — это утилита для отображения списка открытых файлов и процессов, которые их используют. В Linux всё считается файлом, включая сетевые сокеты, каталоги и устройства, поэтому `lsof` может показывать и сетевые соединения.
### Основные флаги `lsof`:

- **`-i` (internet)**:
    
    - Показывает открытые сетевые соединения.
        
    - Пример:
        
        bash
        
        Copy
        
        lsof -i
        
- **`-i :<порт>`**:
    
    - Показывает процессы, использующие определённый порт.
        
    - Пример:
        
        bash
        
        Copy
        
        lsof -i :80
        
- **`-u <пользователь>`**:
    
    - Показывает файлы, открытые определённым пользователем.
        
    - Пример:
        
        bash
        
        Copy
        
        lsof -u root
        
- **`-p <PID>`**:
    
    - Показывает файлы, открытые процессом с определённым PID.
        
    - Пример:
        
        bash
        
        Copy
        
        lsof -p 1234
        
- **`-c <имя процесса>`**:
    
    - Показывает файлы, открытые процессами с определённым именем.
        
    - Пример:
        
        bash
        
        Copy
        
        lsof -c nginx
        
- **`+D <директория>`**:
    
    - Показывает файлы, открытые в определённой директории.
        
    - Пример:
        
        bash
        
        Copy
        
        lsof +D /var/log
        
- **`-n` (no hostnames)**:
    
    - Отображает IP-адреса вместо имён хостов.
        
    - Пример:
        
        bash
        
        Copy
        
        lsof -i -n
        
- **`-P` (no port names)**:
    
    - Отображает номера портов вместо их имён (например, 80 вместо http).
        
    - Пример:
        
        bash
        
        Copy
        
        lsof -i -P


#mtr #сети #маршрутизация
**`mtr`** (My Traceroute) — это мощная сетевая утилита, которая сочетает в себе функции **`traceroute`** и **`ping`**. Она позволяет отслеживать маршрут пакетов от вашего компьютера до целевого хоста, одновременно измеряя задержки и потери пакетов на каждом этапе (hop). `mtr` предоставляет информацию в реальном времени и часто используется для диагностики сетевых проблем.

---

## **Основные возможности `mtr`**:

1. **Трассировка маршрута**:
    
    - Показывает все промежуточные узлы (маршрутизаторы) на пути к целевому хосту.
        
2. **Измерение задержек**:
    
    - Отображает время отклика (пинг) для каждого узла.
        
3. **Статистика потерь пакетов**:
    
    - Показывает процент потерянных пакетов на каждом этапе.
        
4. **Режим реального времени**:
    
    - Обновляет статистику непрерывно, что позволяет наблюдать за изменениями в сети.
        
5. **Поддержка разных протоколов**:
    
    - Может использовать ICMP, TCP или UDP для трассировки.

Что делает?
chmod 600 secret.txt 

Команда `chmod 600` в Linux и Unix-подобных операционных системах изменяет права доступа к файлу или директории.

Конкретно `600` означает:

- **6** для владельца файла: чтение (4) + запись (2) = 6 (права на чтение и запись, но не на выполнение).
    
- **0** для группы: никаких прав (0).
    
- **0** для всех остальных: никаких прав (0).
    

Таким образом, команда `chmod 600 <имя_файла>` устанавливает права доступа так, что:

- Владелец файла может читать и записывать в файл.
    
- Группа и все остальные пользователи не имеют никаких прав доступа к файлу.
    

Это часто используется для защиты конфиденциальных файлов, таких как SSH-ключи (`~/.ssh/id_rsa`), чтобы только владелец мог их читать и изменять.


Сигналы в Linux — это механизм межпроцессного взаимодействия (IPC), который позволяет ядру или одному процессу уведомить другой процесс о наступлении какого-либо события. Сигналы используются для управления процессами, обработки ошибок и асинхронных событий.

---

### Основные концепции сигналов

1. Источники сигналов:
   - Ядро: Например, при попытке доступа к недопустимой памяти (SIGSEGV) или при нажатии Ctrl+C (SIGINT).
   - Другие процессы: Один процесс может отправить сигнал другому с помощью системного вызова kill().
   - Пользователь: Например, через терминал (нажатие `Ctrl+C`).

2. Типы сигналов:
   - В Linux существует около 30 стандартных сигналов. Каждый сигнал имеет уникальный номер и имя (например, SIGINT, SIGTERM).
   - Сигналы делятся на:
     - Убивающие сигналы: Завершают процесс (например, SIGKILL, SIGTERM).
     - Игнорируемые сигналы: Процесс может их игнорировать (например, SIGCHLD).
     - Перехватываемые сигналы: Процесс может перехватить их и обработать (например, SIGINT).

3. Поведение по умолчанию:
   - Каждый сигнал имеет поведение по умолчанию. Например:
     - SIGINT завершает процесс.
     - SIGKILL принудительно завершает процесс.
     - SIGSTOP приостанавливает процесс.

4. Обработка сигналов:
   - Процесс может перехватить сигнал и изменить его поведение с помощью функции-обработчика (signal handler).
   - Если обработчик не установлен, выполняется поведение по умолчанию.

---

### Основные сигналы и их описание

1. SIGINT (2):
   - Описание: Прерывание с клавиатуры. Обычно отправляется при нажатии Ctrl+C.
   - Поведение по умолчанию: Завершает процесс.
   - Пример использования: Остановка длительной операции в терминале.

2. SIGTERM (15):
   - Описание: Запрос на завершение процесса. Это "вежливый" способ завершить процесс.
   - Поведение по умолчанию: Завершает процесс.
   - Пример использования: Завершение процесса с возможностью выполнить cleanup.

3. SIGKILL (9):
   - Описание: Принудительное завершение процесса. Процесс не может его игнорировать или обработать.
   - Поведение по умолчанию: Немедленное завершение процесса.
   - Пример использования: Завершение "зависшего" процесса.

4. SIGSTOP (19):
   - Описание: Приостанавливает выполнение процесса.
   - Поведение по умолчанию: Процесс останавливается и не может быть продолжен до получения SIGCONT.
   - Пример использования: Приостановка процесса для отладки.

5. SIGCONT (18):
   - Описание: Продолжает выполнение приостановленного процесса.
   - Поведение по умолчанию: Возобновляет выполнение процесса.
   - Пример использования: Продолжение приостановленного процесса.

6. SIGSEGV (11):
   - Описание: Ошибка сегментации. Процесс пытается получить доступ к памяти, которая ему не принадлежит.
   - Поведение по умолчанию: Завершает процесс.
   - Пример использования: Отладка программ с ошибками доступа к памяти.

7. SIGHUP (1):
   - Описание: Сигнал "висячего" соединения. Обычно отправляется, когда терминал, из которого запущен процесс, закрывается.
   - Поведение по умолчанию: Завершает процесс.
   - Пример использования: Перезапуск демонов или перечитывание конфигурационных файлов.

---

### Отправка сигналов

Для отправки сигналов используется команда kill или системный вызов kill().

#### Команда kill:
kill -<сигнал> <PID>
Примеры:
- Завершить процесс с PID 1234:
 
  kill -SIGTERM 1234
  
- Принудительно завершить процесс:
 
  kill -SIGKILL 1234
  
#### Системный вызов kill() в C:
#include <signal.h>
kill(pid, sig);
Пример:
kill(1234, SIGTERM); // Отправить SIGTERM процессу с PID 1234

Бастионный хост в сетях — **это специально отведённый компьютер или сервер, который намеренно открыт для публичного интернета**. Его основная цель — обеспечить безопасный доступ к другим ресурсам внутри сети. [4](https://softwareg.com.au/blogs/internet-security/what-is-bastion-host-in-network-security)

Бастионный хост обычно расположен на внешней стороне демилитаризованной зоны организации. Такой узел полностью открыт для атак, так как не защищён ни фаерволом, ни фильтрующим маршрутизатором. [2](https://ru.wikipedia.org/wiki/Bastion_host)

Бастионные хосты используются для **защиты внутренней сети организации от внешних угроз**. Они предоставляют контролируемый доступ для авторизованных пользователей и фильтруют входящий и исходящий сетевой трафик.
